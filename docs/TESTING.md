# 测试策略与覆盖

## 自动化检查

当前自动化由 TypeScript 静态检查、前端生产构建和 Rust 单元测试组成：

```powershell
npm.cmd run check
npm.cmd run build
cargo test --manifest-path src-tauri/Cargo.toml
```

正式交付还必须执行：

```powershell
npm.cmd run release
```

并短暂启动 `src-tauri/target/release/eraw.exe`，确认嵌入前端资源的独立 EXE 不会启动即退出。

## Rust 测试覆盖

V0.1.2 包含 34 项 Rust 测试，重点分为：

| 分类 | 已覆盖内容 |
| --- | --- |
| 布局与解码 | 行/帧对齐、部分帧、MIPI RAW10/12/14、奇数位深、大小端与 MSB |
| CFA | 标准/Quad 站点、Gb/Gr、Phase、裁剪后的排列 |
| 预览 | 缺失数据、L0/L1+、结构保持 LOD、跨瓦片边界、Demosaic 层级稳定 |
| Remosaic | 4×4 重排可逆、同色重建、处理后 Bayer 预览 |
| 任务控制 | 过期瓦片协作取消、像素检查请求上限 |
| 导出 | 位深映射、缺失填充、原始/重排/Demosaic、相位和端序 |

测试目标是验证数据语义和边界条件；不使用“测试图看起来好看”替代数值断言。

## 前端验证现状

前端目前没有独立的单元测试或端到端测试框架。`tsc --noEmit` 可以发现类型和接口不一致，Vite 构建可以发现资源与打包问题，但以下行为仍以人工验证为主：

- 缩放锚点、拖动、滚动条、十字准星和坐标定位。
- 参数栏伸缩、左右布局、悬停提示和输入提交时机。
- 六套主题、不同字号、高 DPI 和异形窗口尺寸。
- 诊断覆盖层、导出字段联动、对话框和键盘操作。
- LOD 切换时 RAW/CFA/Remosaic 的主观连续性。

## 建议人工回归矩阵

每次涉及 RAW、视口或导出时，至少选择小图和大图各一例：

1. 标准 Bayer Unpacked16，检查 L0、适应窗口、连续缩放和 Demosaic。
2. MIPI RAW10/14，检查 packing、行/帧对齐和瓦片边界。
3. Quad CFA，检查四种排列、Phase、仅重排和同色重建。
4. MONO，确认只显示 RAW 强度。
5. 不完整帧或短数据，确认可显示内容、诊断和停止重试。
6. 当前帧三类导出，核对文件大小、CFA 语义和缺失填充统计。

超大分辨率、偶发瓦片刷新和视觉质量适合人工测试；除非能够建立稳定、可解释的数值夹具，不强求高成本的截图自动化。

## 当前测试空白

- 没有浏览器级交互回归和视觉快照。
- 没有固定硬件上的渲染耗时基线。
- 区域选择尚未开放 UI 或连接统计任务，目前仅完成模型和叠加层实现。
- 100000×100000 是前端参数边界，不代表已对所有存储格式完成该尺寸的资源压力测试。
