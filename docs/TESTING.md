# 测试策略与覆盖

## 自动化检查

`--skill` 的 Release 检查在仓库之外的工作目录执行，验证完整输出与 `skill/eraw-viewer/SKILL.md` 一致且不依赖旁置文件，并实际预检 skill 中的调用示例。前端运行时目录测试确认七种语言均恰好插入一篇 CLI 专页、位于工作流之后、章节 ID 唯一，并保留全部原章节；CLI 页面示例共用同一份命令文本。

新增 CLI 验证使用 `npm.cmd run test:cli`，须先执行 `npm.cmd run release`。该检查以 10 秒子进程超时运行已构建 EXE 的帮助、版本和 `--check`，验证英文输出、stdout/stderr、退出码、中文/空格路径和调用方相对路径；不会打开 GUI 或启动开发服务器。Rust 测试另覆盖 CLI 参数、packing/位深冲突、CFA 模式限制、预检边界和部分帧。多实例偏好测试模拟持有旧快照的窗口，验证按字段保存不覆盖无关修改。

当前自动化由 TypeScript 静态检查、前端生产构建和 Rust 单元测试组成：

```powershell
npm.cmd run check
npm.cmd run test:frontend
npm.cmd run build
cargo test --manifest-path src-tauri/Cargo.toml
```

`test:frontend` 为每项测试设置 30 秒超时。前端自动化运行纯 Node 测试、静态检查、有限构建和 Rust 测试，不启动 Vite/Tauri 开发服务器。Linux 原生 WebView 冒烟使用真实 Release 可执行文件和有界 WebDriver 进程，允许其本机临时端口；测试结束关闭应用与驱动，不保留常驻服务。交互检查均须限时并清理本次进程。

正式交付还必须执行：

```powershell
npm.cmd run release
```

并短暂启动 `src-tauri/target/release/eraw.exe`，确认嵌入前端资源的独立 EXE 不会启动即退出。

## 建议人工回归矩阵

每次涉及 RAW、视口或导出时，至少选择小图和大图各一例：

1. 标准 Bayer Unpacked16，检查 L0、适应窗口、连续缩放和 Demosaic。
2. MIPI RAW10/14，检查 packing、行/帧对齐和瓦片边界。
3. Quad CFA，检查四种排列、Phase、仅重排和同色重建。
4. MONO，确认只显示 RAW 强度。
5. 不完整帧或短数据，确认可显示内容、诊断和停止重试。
6. 当前帧三类导出，核对文件大小、CFA 语义和缺失填充统计。
7. 依次切换七种语言，检查主窗口、主题菜单、设置、快捷键、关于和导出窗口；英文、西班牙文、法文、德文界面不应残留非专有名称的中文。

瓦片边界回归应包含 `1920×1080` MIPI RAW14 Quad RGGB 小图，在适应窗口且状态栏显示 `L0 · 100%` 时依次检查 RAW、CFA 与 Remosaic，重点观察源图像第 256、512、768、1024 行附近；切换“实际像素”前后不应改变行相位。同时保留大分辨率样本用于确认高层 LOD 行为未受影响。

超大分辨率、偶发瓦片刷新和视觉质量适合人工测试；除非能够建立稳定、可解释的数值夹具，不强求高成本的截图自动化。
