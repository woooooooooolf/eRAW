# 测试策略与覆盖

## 自动化检查

当前自动化由 TypeScript 静态检查、前端生产构建和 Rust 单元测试组成：

```powershell
npm.cmd run check
npm.cmd run test:frontend
npm.cmd run build
cargo test --manifest-path src-tauri/Cargo.toml
```

`test:frontend` 为每项测试设置 30 秒超时。自动化流程只运行纯 Node 测试、静态检查、有限构建和 Rust 测试，不启动 Vite/Tauri 开发服务器，也不依赖后台服务或端口探测；需要交互检查时只使用 Release EXE，并由执行者显式限时和关闭进程。

正式交付还必须执行：

```powershell
npm.cmd run release
```

并短暂启动 `src-tauri/target/release/eraw.exe`，确认嵌入前端资源的独立 EXE 不会启动即退出。

## Rust 测试覆盖

V0.2.11 包含 35 项 Rust 测试，重点分为：

| 分类 | 已覆盖内容 |
| --- | --- |
| 布局与解码 | 行/帧对齐、部分帧、MIPI RAW10/12/14、奇数位深、大小端与 MSB |
| CFA | 标准/Quad 站点、Gb/Gr、Phase、裁剪后的排列 |
| 预览 | 缺失数据、L0/L1+、结构保持 LOD、跨瓦片边界、Demosaic 层级稳定 |
| Remosaic | 4×4 重排可逆、同色重建、处理后 Bayer 预览 |
| 任务控制 | 过期瓦片协作取消、像素检查请求上限 |
| 文件释放 | Windows 下关闭文档后释放内存映射，允许独占打开和重命名源文件 |
| 导出 | 位深映射、缺失填充、原始/重排/Demosaic、相位和端序；并行测试使用唯一临时路径 |

测试目标是验证数据语义和边界条件；不使用“测试图看起来好看”替代数值断言。

## 前端验证现状

前端没有通用端到端测试框架。`test:frontend` 当前包含 36 项短时测试，使用 Node 内置测试运行器和项目已有的 TypeScript 编译器，覆盖应用设置默认值、旧值迁移与非法值回退，主题目录唯一性、九套主题的正文/辅助文字/分组标题对比度和宽窄主题菜单布局，存储方式优先的参数顺序、固定位深和容器参数显隐规则，系统语言映射、七语目录完整性与占位符一致性、语言自称、数值输入归一化、关闭文件命令与基于 TypeScript AST 的视口清理检查、Demosaic 与 R/G/B 的控件层级及命中区、通道数值语义与着色规则、关闭高倍率数值后的网格保留及 DN 请求抑制、像素网格颜色校验与 Canvas 应用、缺失数据预设与颜色校验、侧边栏接线、GPU 标记识别和全局棋盘相位、原生全屏 capability、画布尺寸往返变化时的中心锚定，以及奇数视口尺寸和常见 DPR 下的 100% 相机物理像素对齐；`tsc --noEmit` 与有限的 Vite 生产构建继续负责类型、资源和打包检查。以下行为仍以人工验证为主：

- 缩放锚点、拖动、滚动条、十字准星和坐标定位。
- 参数栏伸缩、左右布局、悬停提示和输入提交时机。
- 九套主题、不同字号、高 DPI 和异形窗口尺寸。
- 七种语言的即时切换、菜单自称、对话框翻译，以及 960×640 最小窗口中的长文本溢出。
- F11 进入全屏后窗口覆盖当前显示器、Windows 边框与任务栏隐藏，图像观察中心和缩放比例保持不变；再次按 F11 后窗口尺寸、位置和图像观察中心恢复。
- `Ctrl+W` 关闭文件后可立即重命名、覆盖或删除原文件，画布和文件相关状态清空，再次打开文件时保留 RAW 参数与处理配置。
- 诊断覆盖层、导出字段联动、对话框和键盘操作。
- LOD 切换时 RAW/CFA/Remosaic 的主观连续性。
- “画面呈现”在侧边栏宽度上下限、九套主题和七种语言下的排版；通道颜色/灰度、像素值策略、像素网格颜色、深浅棋盘及自定义纯色的即时切换和重启恢复。
- 缺失数据棋盘在各 LOD、瓦片边界和拖动过程中的相位连续性；纯色只影响文件内缺失像素，图像边界外仍透明。
- Demosaic 主项与 R/G/B 子项在 960px 最小窗口、七种语言和九套主题下的层级、配色及键盘焦点。

## 建议人工回归矩阵

每次涉及 RAW、视口或导出时，至少选择小图和大图各一例：

1. 标准 Bayer Unpacked16，检查 L0、适应窗口、连续缩放和 Demosaic。
2. MIPI RAW10/14，检查 packing、行/帧对齐和瓦片边界。
3. Quad CFA，检查四种排列、Phase、仅重排和同色重建。
4. MONO，确认只显示 RAW 强度。
5. 不完整帧或短数据，确认可显示内容、诊断和停止重试。
6. 当前帧三类导出，核对文件大小、CFA 语义和缺失填充统计。
7. 依次切换七种语言，检查主窗口、主题菜单、设置、快捷键、关于和导出窗口；英文、西班牙文、法文、德文界面不应残留非专有名称的中文。

瓦片边界回归应包含 `1920×1080` MIPI RAW14 Quad RGGB 小图，在适应窗口且状态栏显示 `L0 · 100%` 时依次检查 RAW、CFA 与 Remosaic，重点观察源图像第 256、512、768、1024 行附近；切换“实际像素”前后不应改变行相位。同时保留大分辨率样本用于确认高层 LOD 行为未受影响。

超大分辨率、偶发瓦片刷新和视觉质量适合人工测试；除非能够建立稳定、可解释的数值夹具，不强求高成本的截图自动化。

## 当前测试空白

- 没有浏览器级交互回归和视觉快照。
- 没有固定硬件上的渲染耗时基线。
- 区域选择尚未开放 UI 或连接统计任务，目前仅完成模型和叠加层实现。
- 100000×100000 是前端参数边界，不代表已对所有存储格式完成该尺寸的资源压力测试。
